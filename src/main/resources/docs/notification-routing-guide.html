알림 타입별 이동 가이드

알림 목록(GET /api/notifications)의 아이템을 클릭했을 때 FE가 어느 화면으로 이동해야 하는지 정리한 개발 환경 전용 문서입니다.

한눈에 보기

알림 아이템의 type으로 이동 방식을 고르고, arguments[]에서 필요한 targetType의 targetId를 꺼내 이동 대상을 정합니다.

{
  "id": "알림 ID",
  "type": "POST_COMMENT",
  "arguments": [
    { "targetType": "USER",    "targetId": "행위자 사용자 ID" },
    { "targetType": "POST",    "targetId": "게시글 ID" },
    { "targetType": "COMMENT", "targetId": "댓글 ID" }
  ]
}

타입별 이동 위치

type arguments에 담기는 targetType 이동 위치 FE 구현 방안
POST_COMMENT USER, POST, COMMENT 내 게시글에 달린 해당 댓글 POST의 targetId로 게시글 상세 화면으로 이동한 뒤, COMMENT의 targetId에 해당하는 댓글 위치로 스크롤하고 강조합니다.
COMMENT_REPLY USER, POST, COMMENT 내 댓글이 달린 게시글의 해당 답글 POST의 targetId로 게시글 상세 화면으로 이동한 뒤, COMMENT의 targetId에 해당하는 답글 위치로 스크롤하고 강조합니다. 답글이 접혀 있다면 부모 댓글의 답글 목록을 펼친 뒤 이동합니다.
COMMENT_LIKE USER, POST, COMMENT 좋아요를 받은 내 댓글 POST의 targetId로 게시글 상세 화면으로 이동한 뒤, COMMENT의 targetId에 해당하는 댓글 위치로 스크롤하고 강조합니다.
FOLLOWER_POST USER, POST 내가 팔로우한 사용자가 새로 작성한 게시글 POST의 targetId로 게시글 상세 화면으로 이동합니다.
POST_LIKE USER, POST 좋아요를 받은 내 게시글 POST의 targetId로 게시글 상세 화면으로 이동합니다.
FOLLOW USER 나를 팔로우한 사용자의 프로필 USER의 targetId로 해당 사용자의 프로필 화면으로 이동합니다. 수신자 본인은 arguments에서 제외되어 내려오므로 USER는 항상 팔로우한 사용자입니다.

공통 규칙

  • targetType 기준으로 찾기: arguments의 순서에 의존하지 말고 targetType이 일치하는 첫 번째 항목의 targetId를 사용합니다.
  • 대상이 없을 때: 필요한 targetType이 arguments에 없거나, 이동한 화면에서 게시글·댓글·사용자 조회가 실패(삭제됨 등)하면 이동을 멈추고 "삭제되었거나 볼 수 없는 콘텐츠입니다" 같은 안내를 보여줍니다. 댓글만 사라진 경우에는 게시글 상세 화면에 머무릅니다.
  • 읽음 처리: 이동과 함께 PATCH /api/notifications/read에 { "notificationIds": ["알림 ID"] }를 보내 읽음으로 표시합니다. 이동 자체는 읽음 처리 응답을 기다리지 않아도 됩니다.
  • 새 타입 대비: 이 문서에 없는 type을 받으면 이동하지 않고 알림 목록에 머무릅니다.
